## 4. In progress now: a fully stable tool list

The remaining cache miss is the first call of every episode: the tool list still differs between task types (task tools and `save_final_answer`'s `answer` field). In the pilot those rewrites cost $3.61, against $0.29 as cache reads. Planned (`--tool-list stable`, to become the default):

- One tool list for every episode and phase: all task types' tools, one fixed order, with one `save_final_answer` whose `answer` description covers all three formats (code's `no_bug`/`bug` enum moves into the description; dispatch already validates it).
- Dispatch still rejects a tool from another task type or another phase. The error wording becomes more deployment-like for tools that are listed but not usable here (e.g. "not available in this workspace" rather than "not one of the tools you are given"), to reduce eval-awareness cues. We can't remove them entirely: a listed tool that refuses is itself a cue.
- The phase openings already name the tools that apply, so the mode lives in message content, as the API docs recommend for models without mid-conversation tool changes (Sonnet 5 has none; checked, §13).
- Checks: offline, the tool list must be byte-identical across all task types and phases, and prompts unchanged apart from the merged `answer` description. Live, a two-episode run (~$1) must show cache reads at the episode-2 start.
